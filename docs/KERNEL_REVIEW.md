# 内核审查与改进计划

审查日期：2026-10-29。方法：本地源码静态检查，覆盖 `Project/RTOS/`、HAL 示例公共内核及综合演示内核。下列内容是待办，尚未在本次导入中修复，也未经上板复现。

## 已有能力

- 静态任务创建，任务栈由调用者提供。
- 最高优先级就绪任务选择与同优先级轮转。
- SysTick 节拍、任务延时、同步对象等待超时。
- 计数信号量、支持递归的互斥量、拷贝式消息队列。

## 优先修复

| 优先级 | 问题 | 代码依据与影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 缺少调度器启动保护 | HAL 的 `HAL_Init()` 启用 SysTick，但内核 `SysTick_Handler()` 无条件请求 PendSV。初始化期间 `current_tcb` 可能为 NULL，PSP 尚未建立；PendSV 会直接保存上下文。 | 引入运行状态和统一启动入口；启动前保留 HAL 时基，禁止任务调度；首次切换在受控条件下完成。 |
| P0 | PendSV 调用 C 函数时栈对齐不符合调用约定 | `push {lr}` 后直接 `bl schedule`，使原本 8 字节对齐的 MSP 偏移 4 字节。 | 按 Arm AAPCS 维护 C 调用边界上的 8 字节栈对齐。 |
| P1 | M4F 上下文支持不完整 | PendSV 仅保存 R4-R11，没有按任务保存异常返回值，也没有浮点寄存器保存恢复逻辑。 | 正确处理 EXC_RETURN 与浮点上下文；验证浮点和整数任务交替运行。 |
| P1 | 临界区不恢复调用前状态 | 多数 API 在退出时无条件 `__enable_irq()`。外层已关中断时会被提前打开。 | 保存、恢复原中断屏蔽状态，规定嵌套规则，禁止在临界区调用阻塞 API。 |
| P1 | 互斥量没有优先级继承 | `xMutexTake()` 只阻塞等待者，没有提升持锁任务的有效优先级。 | 实现继承和恢复，并考虑递归持锁、多锁及等待者超时。 |
| P1 | 等待者唤醒顺序可能导致饥饿 | `task_block_on_event()` 使用头插，Give/Send/Receive 从等待链表头唤醒。 | 按优先级排序，同优先级 FIFO。 |
| P1 | 重试重新计算完整等待时间 | 信号量、互斥量、队列被唤醒后重新竞争；竞争失败再次使用原 `waitTicks` 阻塞。 | 使用总截止时间，重试时计算剩余等待时间。 |
| P1 | 任务创建缺少边界检查 | 未检查参数、最小栈空间或重复 TCB；`MAX_TASKS` 仅限制调试登记，任务此前已加入就绪链表。 | 返回创建结果，校验参数、容量及重复创建，记录栈范围。 |
| P1 | 任务函数返回没有安全处理 | 初始任务 LR 填入 `0xFFFFFFFD`，它不应作为普通线程函数的返回地址。 | 使用任务退出处理函数，选择安全终止或断言并记录错误。 |
| P2 | 任务状态维护不完整 | `schedule()` 将新任务设为 RUNNING，但没有把被切走且仍就绪的旧任务恢复为 READY。 | 维护一致的任务状态转换与查询。 |

根目录内核还把节拍重载固定为 168000，HAL 版本则存在使用 `SystemCoreClock` 及更新时钟后的不同变体。应统一时钟和 tick 配置，并把 PendSV 优先级设置纳入内核启动过程，而非依赖每个应用手工设置。

## 后续功能

1. ISR 专用信号量/队列接口、调用上下文和中断优先级检查。
2. tick 查询、毫秒转换、绝对周期延时 `delay_until()`。
3. 栈填充与剩余量统计、栈溢出检测、断言、HardFault 寄存器记录。
4. 任务参数、挂起/恢复、优先级调整及调度锁；按实际需求决定是否增加删除任务。
5. 软件定时器、任务通知、事件标志。
6. 空闲任务 WFI、低功耗及 Tickless。

保持静态内存分配是可行的设计选择，动态堆不是当前必要功能。

## 验证建议

- 启动前长时间外设初始化，确认 HAL tick 工作且 PendSV 不提前运行。
- 多优先级、同优先级任务持续切换；整数任务和浮点任务交替运行。
- 多任务竞争信号量、互斥量和满/空队列，核对唤醒顺序和总超时时间。
- 低优先级持锁、高优先级等待、中优先级持续运行，检查优先级继承。
- 嵌套临界区、中断到任务通信、栈不足、重复创建及任务意外返回。
